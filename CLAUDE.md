# Travel plans repo

**Start here on a new machine or session: read `docs/v2/PLAN.md` (the single plan: requirements, order, status, next tasks, open decisions), then `HANDOVER.md` (setup), then `docs/v2/build/public-site/EXECUTION-PLAN.md` for task detail and `BACKLOG.md` for row status.** `main` is the new public site (v2); the old site is the tag `legacy-final`; the live site is unchanged until the owner approves go-live. For research, `research/README.md`.

Each trip is **data**:
- `data/trips/<id>/trip.json`, written only through `node core/bin/ops.ts`;
- `data/schedules/<id>.json`;
- records in `data/capture/<id>/`, with sidecars in `data/suitability/<id>/` and `data/relevance/<id>/`;
- prose research in `research/trips/<id>/`.

The web app (`web/`) renders it. **No new HTML:** a request to change how a page looks is a `web/` change (spec in
`docs/v2/`, then `travel-builder`, the design review and the verifier). The 14 old pages in `legacy/<folder>/` are frozen
until backlog 7.11: never edit them except to move data out.

**Skills** live only in `.claude/skills/<name>/SKILL.md`, the one folder Claude Code loads, and point into
`research/README.md`:
- `trip`: plan or revise a trip as data;
- `research`: facts, gaps, refreshes, photos and links for a place, route, offer or event;
- `location`: capture a place to remember.

Decision record: `docs/v2/SKILLS-AND-DATA-ONLY.md`.

legacy outputs (`legacy/locations/index.html` and the globe pins `legacy/globe/assets/data/places.json`); never hand-edit

## Folder contract (since the cleanup, Oct 2026)

Code and every script live in `core/`, `web/` and `tools/`. Authored data the product reads lives in `data/` (records,
sidecars, run records, locations, vocab). Generated files stay where their tool writes them, carry a "Generated ... Do not
edit" line, and are rebuilt, never edited: `data/schema/**` (except `difficulty-map.json` and `freshness.json`), the per-type
checklists `research/types/**` and the report `research/reports/trip-tag-conflicts.md`, `data/sources/registry.json`, `data/suitability/scope.json`,
`web/redirects.json`, `web/data-snapshots/**`, `data/locations/WISHLIST.md`. **All research lives in `research/`**, and
`research/README.md` is its map: the method in `method/` (capture contract, `kinds/`, `lanes/`, suitability, relevance,
sources and licences), the per-type checklists in `types/` (generated by `capture.ts build`; never add a file
there), output formats and templates in `formats/`, raw captures in `inbox/`, per-trip findings in `trips/<folder>/` (index:
`trips/README.md`), run notes in `runs/`, audits in `audits/`, research reports in `reports/`, imported notes in
`vault-notes/`, the work queue in `backlog.md` (`research/backlog.md`), and the script
index in `tools.md`. Nothing else goes at the `research/` root. **Decisions** live in `docs/v2/`: plan, TODO, specs, design,
build briefs, reviews. Superseded documents go to `docs/archive/v1/`, and nothing live links into it. Skills
(`.claude/skills/`) and agents (`.claude/agents/`) are thin wrappers that point into `research/`; never copy the method into
them. Removed things live in `archive/*` tags, never in a folder. Commit a screenshot only when a spec or review names it;
verification shots go to `web/test-results/shots/` (gitignored).

`legacy/<folder>/` holds the 14 old pages, their `PLAN.md` and builders, frozen until backlog 7.11 (no edits except moving
data out). Check-all's "folder contract" stage (CLN-5) will enforce this. Deployment is out of scope until the hosting is
chosen (`docs/v2/PLAN.md` R-8). Never run `./publish.sh` in a mode that deploys; `python3 tools/publish.py --dry-run`
stages `.site/` for the e2e harness until API-0.

`gallery.py inject` is frozen. Photo research is `research/README.md` 3e. Never search Commons from parallel agents.

The new site's home is `web/app/page.tsx`. The old hub at nks-travel.pages.dev is built by `tools/hub.py` inside

## Gotchas
- `"private": true` in `legacy/MANIFEST.json` takes a page down on the old site **and** hides the trip from the web app
  (`web/lib/public/sources.ts` reads it). For a data trip, `trip.visibility` decides (after TD-2).
- Renaming a trip folder leaves the old path live on Cloudflare Pages (earlier deployments' assets persist).
- Capture refs that start `legacy/canadian-rockies-sept-2029/...` are record ids, not paths. Never rewrite them.
- `tools/hooks/prepublish.sh` runs as a PreToolUse hook on Bash commands that mention publishing. A command line that
  only contains the word can trigger it; use another wording for a grep.

## Platform (in progress)
`core/` holds the schema (Zod, exported to `data/schema/generated/`) and the validator; run `bash tools/check-all.sh` before publishing.
Locations are schema v3 (`data/vocab/tags.json` holds the tags, captures live in `research/inbox/`); day checks are `core/src/checks/`, the operation catalogue `core/src/ops/catalogue.ts` (exported to `data/schema/generated/ops.json`), and `.mcp.json` registers the read-only MCP server `core/bin/mcp.ts`.

Sun, twilight and darkness times come from `core/src/sun` (`node core/bin/sun.ts --lat .. --lon .. --zone .. --date ..`); longitude is positive EAST (Reykjavik is -21.94). Negating it shifts every time by 8 minutes per degree, which is how four legacy scripts went wrong until S1 (`research/audits/sun-audit-2026-10-18.md`). Never hand-copy the formula or take times from memory.

`web/` is the Next.js app (a static export of home, trips, places, about until lane API-0 makes it a server build with `/api/v1/` route handlers; see `docs/v2/PLAN.md`); `tools/publish.py` merges it with the frozen legacy pages for the old site only, until backlog 7.11. Colour comes only from `web/app/themes.css`, generated by `python3 tools/theme_tokens.py`.

Capture contract (3a.12 steps 1-4, lane CC): `data/vocab/types.json` is the one authored file (the 15-domain, 61-category, 324-id type tree, the suitability profile rows, layer and offer-class rules, marks per node); `core/src/schema/capture/properties.ts` is the property registry. `node core/bin/capture.ts fields --type <id>` is the checklist a researcher or crawler follows, `explain`, `gaps --trip` and `run --check` are the rest; `capture.ts build` writes `data/schema/capture/*`, `research/types/*` (CLN-R moves it to `research/types/*`) and `data/schema/suitability-applicability.json` (never edit those; `build --check` runs in check-all). Records are place, route, offer or event in `data/capture/<trip>/*.json` (`capture/1`, joined to the suitability and relevance sidecars by ref); a lift's suitability block sits on its `offer/<ref>#ticket`. Gotchas: a new TYPE is one entry in types.json, a new PROPERTY is a registry change; the profile of a record's type must equal the profile of its kind/subkind (E_CAP_TYPE); the 61-record migration ran once (`capture.ts migrate` refuses to run again) and `data/capture/migration-ledger.json` pins that every pre-migration leaf still exists with the same value (new records and leaves are allowed; the count tests cover `migrated.json` only).

Operations (P4a): every write to `data/trips/` is an operation in `core/src/ops/` (`node core/bin/ops.ts <name> --input <file or ->`, or `node core/bin/serve.ts` for the local API); each returns an inverse, and `trip.restore` undoes it. Book-by dates are `core/src/bookings/`, sun times `core/src/sun/`.

## Agents and models (since 18 Oct 2026)

Delegate by kind of work. The project agents are in `.claude/agents/`. The v2 plan (`docs/v2/`) is on `main`; its entry point is `docs/v2/PLAN.md`. The old integration branch `claude/serene-goldberg-wtn3di` was deleted on 21 Oct 2026 and kept as the tag `archive/claude-serene-goldberg-wtn3di` (with `archive/phase-p3b`, `archive/phase-p4b` and `archive/wip-*`); new work branches from `main`.

| Work | Agent | Model |
|---|---|---|
| Plans, specs, feature pages, decisions, build briefs | `travel-planner` | Opus |
| Research: places, trails, sights, adventures, stays, coordinates, links, booking windows | `travel-researcher` | Opus |
| Coding and tests in web/, core/, tools/ | `travel-builder` | Sonnet |
| UI/UX and design-system review, foundation changes | `travel-design-reviewer` | Opus (not Fable, owner 18 Oct) |
| Independent checks and visual sweep before reporting done | `travel-verifier` | Sonnet |
| Quick file search | `explorer` (global) | Haiku |

Every UI round ends with `travel-design-reviewer`, then `travel-verifier`. Parallel agents get disjoint file ownership. Commons searches stay sequential.

### Model by task complexity (owner, 21 Oct 2026)

The table above is the default per agent. The coordinator overrides it per task with the Agent tool's `model` parameter, picking the cheapest model that can do the task well. Never Fable.

| Complexity signal | Model | Examples |
|---|---|---|
| Mechanical, no judgement: search, count, list, rename, format, run a command and summarise, link checks | Haiku | find every reference to a folder, grep counts, hash duplicates |
| Well specified, inside owned files, a brief and acceptance check exist: implement, write tests, verify, screenshot sweep, fill data to a clear contract | Sonnet | phase A lanes, test-race fixes, trail-fact rendering, `travel-verifier` runs |
| Ambiguous or cross-cutting: no spec yet, a shared contract or new abstraction, more than three interdependent files, privacy or security, a hard algorithm, taste (design review), research that needs judgement, gates and audits | Opus | API-1 contracts and `CatalogueStore`, the globe fit model, schema diffs, plans, design review, public-output and code audits |

Rules: start at the lowest model that fits. Escalate one step when a hand-back shows a judgement error, the same fix fails twice, or the task turns out to touch a shared contract. Step down for mechanical follow-ups (a renamed import, a snapshot update). A builder task that creates a shared contract is Opus even though it is code. Reviews and audits are never below the model that wrote the work. Record the model in each lane's hand-back so the choice can be judged afterwards.
