# P5b1: creation flow inputs, drafts, undo, autosave, Download/Import

## Goal

Build the first half of the trip creation flow at `/new/`: screens S0-S6 with a live match counter and a catalog candidate picker, all writing to one `TripDraft` that is a trip.json document plus an operation log. Drafts autosave to IndexedDB, undo works for 100 steps across reloads, they can be downloaded and imported as `trip.json`, and "Make me a first draft" produces a simple fallback draft for the day board of P5b2.

## Prerequisites (state at start)

P4c and P3b merged on `main` (P5a, P5c, P6 may run in parallel).

- `core/`: schemas, validator (`validateDoc`), day checks, operations as pure functions with `inverse` (`core/src/ops/`), `MemoryStore`, edition resolution, sun.
- `web/`: `EntityPage` in four views, `FilterBar`, `DetailSheet`, `/places/`, format helpers, theme; `/data/places.json` and entity views at build; catalog rows for the Rockies and Patagonia in `data/catalog/**` with coordinates (or `W_NO_COORDS`).
- Spec: `docs/PLAN-platform.md` 0B.1-0B.3 (design rules, S0-S9, unknown counting, Download/Import, undo and autosave), 0B.6, 0B.7, 4.12 (components), 0A.5 (inputs and the v1 fallback shape), 4.13.

## Files you own

### Step 1. TripDraft and the operation log

`web/lib/draft/`: `TripDraft = {id, doc: TripJson, log: OpRecord[], cursor}`; every change is `applyOp(draft, name, input)` running the same pure functions as `core/src/ops/` on a `MemoryStore` (actor `{id: "u_local", via: "ui"}`), validating with `core`'s validator, recording `{seq, name, input, inverse, at}`. Undo applies the inverse at the cursor; redo re-applies; at least 100 steps; a new op after an undo drops the redo tail. Unit tests: 100 random ops then 100 undos restore the original bytes; redo; validation failure leaves the draft unchanged.

Commit `P5b1 step 1: TripDraft as trip.json plus an operation log`.

### Step 2. Persistence, autosave, Download/Import

IndexedDB through `idb`: stores `drafts` (id, doc, cursor, updated) and `ops` (draft id + seq). Every op is persisted before the UI acknowledges it. On load, `/new/` lists drafts and resumes the last one. "Download trip.json" writes `<slug>.private.trip.json` (the whole document; the file name says it includes private fields). "Import trip.json" validates with `core`, shows errors in the plan 4.7 format, and creates a new draft id unless the user chooses "Replace the draft with the same id". The S9-style warning "This draft has not been downloaded since its last 20 changes" appears in the draft menu (plan 4.13).
Tests (Vitest with `fake-indexeddb`): persistence round trip; import of a broken file shows codes; Download/Import round trip gives an identical document. Playwright `web/tests/new-autosave.spec.ts`: make five changes, close the page abruptly (`page.close({runBeforeUnload: false})`), open a new page: the draft and the undo history are back.

Commit `P5b1 step 2: IndexedDB autosave, undo across reloads, Download and Import`.

### Step 4. S6 candidate picker and the fallback first draft

`CandidatePicker`: `EntityPage` in picking mode (checkboxes, "+40 min from base" estimate labelled as an estimate, eligibility badges, "Add everything I ticked"); picks go to the draft's Unscheduled tray (items with `day` unset are not valid trip.json, so the draft keeps picks in a draft-only `unscheduled` list stored beside `doc` in the draft, never in trip.json). "Make me a first draft" calls `firstDraft(input)` from `core/src/planner/index.ts`, which in this phase is `core/src/planner/fallback.ts`: picks grouped by nearest base (straight-line distance; a pick without coordinates stays unscheduled with the 0B.7 "Item without coordinates" message), spread across that base's nights in score order (`3*tag_match + 2*must_do + 1*freshness`), at most `pace + 1` items a day, no times, deterministic (ties by id). P7 later replaces the body of `firstDraft` behind the same signature.
Tests: `core/test/planner/fallback.test.ts` (determinism, grouping, the no-coordinates rule, the per-day cap); Playwright `web/tests/new-minimum.spec.ts`: the four-answer minimum plus "Make me a first draft" yields a draft whose `doc` validates with zero errors.

## Pitfalls

1. `TripDraft.doc` is always a valid trip.json; draft-only state (unscheduled picks, cursor) lives beside it, never inside it.
2. Every change is an operation; do not mutate the document directly in a component.
3. A browser-only draft has no backup except Download; the warning matters.
4. Private traveller fields are kept in the draft and in the downloaded file; they must never reach `/data/*.json` or a public build (the privacy test still passes).
5. `firstDraft` keeps its signature so P7 can replace the body.
6. `fake-indexeddb` in unit tests; real IndexedDB only in Playwright.
7. Never `cd`; never `git add -A`.
