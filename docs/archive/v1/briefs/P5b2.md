# P5b2: day board, board map, keyboard moves, `/edit/`

## Goal

Build S7, the day board beside a map, where a draft or an existing trip is arranged by drag-and-drop and by keyboard, with legs, arrival times and day checks recomputed on every change. Serve the same board at `/edit/?trip=<slug>`, saving through the local API on the owner's machine and explaining where editing works on the deployed site.

## Prerequisites (state at start)

P5b1 merged on `main` (P5a, P5c, P6 may run in parallel).

- `web/lib/draft/` (TripDraft = trip.json plus an operation log, undo, IndexedDB autosave, Download/Import), `/new/` S0-S6 with the match counter and candidate picker, the Unscheduled list, `firstDraft` (fallback) in `core/src/planner/`.
- `core/`: operations (`item.add`, `item.move`, `item.update`, `item.remove`, `item.pin`, `day.*`, `base.set`, `track.set`), day checks with `W_*` codes, sun, book-by; `node core/bin/serve.ts` (local API, `POST /api/v1/ops/<name>`, `GET /api/v1/trips/<slug>`).
- `web/components/map/` (`MapView` frozen; P5a's `DayMap` may exist), format helpers, `EntityPage`.
- Spec: `docs/PLAN-platform.md` 0B.2 (S7, draft-and-edit loop, pins), 0B.6 (interactions, keyboard, phone, reduced motion, text equivalents, focus), 0B.7 (guardrail messages shown on cards), 4.7 (editing flag), 4.12.

## Files you own

`web/app/edit/page.tsx`, `web/components/create/board/**` (`DayBoard`, `DayColumn`, `ItemCard`, `LegChip`, `BaseSlot`, `UnscheduledTray`, `BoardMap`, `MoveToDayMenu`, `ChecksPanel`), `web/lib/board/**` (leg estimates, arrival times, the save adapter for the local API), `web/tests/**` files named `board-*` and `edit-*`; append-only `web/package.json` (`@dnd-kit/core@6.3.1`), the S7 entry in the `/new/` step rail (one line in `web/app/new/`).

Must not touch: `web/components/{plan,map,globe}/**` (import only), `web/app/[slug]/**`, `core/**`, `web/lib/draft/**` except calling its API, `.claude/**`.

### Step 3. BoardMap

`BoardMap` wraps `MapView`: each day in its colour from a fixed colour-blind-safe palette of 8 hues with distinct dash patterns (colour is never the only cue), numbered pins, legs as dashed straight lines (estimates) or stored geometry, fit-to-day on day selection and "Whole trip"; click (long-press on phones) offers "Add a stop here" with the nearest catalog rows within 500 m, else a custom item (P5b3 builds custom items; here, offer the catalog rows only and leave the custom branch disabled with a note); drag numbered pins to reorder within a day (same operation as the board). The sr-only table of items and legs per day follows the map.

## Pitfalls

1. Keyboard and "Move to day" first, drag second (R28): the keyboard path is the acceptance, not an extra.
2. Every board action is an operation; undo comes from the log, not from component state.
3. Estimates are labelled everywhere; mountain roads make them wrong (R29).
4. The local API binds `127.0.0.1`; never point the deployed build at it (`NEXT_PUBLIC_EDITING=off` there).
5. Kill servers by PID; never `cd`; never `git add -A`.
