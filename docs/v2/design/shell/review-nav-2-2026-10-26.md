## 1. Verdict

**Not approved yet.** The rows, groups, menu, "No longer listed" state, empty state and the copy sheet's replace and done
steps match the spec and read well in both themes at every width; the row lines fit at 320 with no ellipsis on the date or
party (T1). The critical item and the three important items below are the must list. The critical one (C1) predates NAV-2,
which only uncovered it, but it is site-wide and blocks the public site, so it goes first.

## 2. Must fix

### C1. Critical: every page fails to load when `localStorage` throws on access

- **Screen:** any page, all widths and themes, in a browser that blocks site data (Safari "Block all cookies", some in-app
  webviews and sandboxed frames). The builder reproduced it on `/trips/dolomites-2027/` and `/places/lago-di-braies/`
  ("This page couldn't load").
- **What is wrong:** `web/lib/format/prefs.ts` `snapshot()` calls `window.localStorage.getItem(PREFS_KEY)` outside a
  `try`, and it is the `getSnapshot` of `useSyncExternalStore` in `usePrefs()`. The render throws and the route's error
  boundary replaces the page. `usePrefs` is used by the footer's `UnitSwitch`, which is on every page, so this is not limited
  to trip and place pages: expect home, lists, the globe and `/mine/` to fail the same way (confirm with the
  throwing-getter script). Two more unguarded readers make the same failure: `web/components/suit/Interactions.tsx`
  `applyUnits()` (in an effect, so it also reaches the boundary) and `web/lib/entities/savedViews.ts` (`loadViews` and
  `storeViews` take `window.localStorage` as a default argument, evaluated outside any `try`, inside a `useState` initialiser
  in `SavedViewsMenu`).
- **Why it matters:** the public read-only site is the first priority. A family whose browser keeps no site data gets
  nothing at all, not a reduced site. Units are a preference, so failing to read them must cost nothing. P4, T2.
- **Fix (where it belongs): one site-wide safe-storage helper, not per-file patches.**
  1. New `web/lib/storage/safe.ts`, no imports (so it can sit in the start chunk for a few bytes):
     `readLocal(key): string | null`, `writeLocal(key, value): boolean`, `readSession(key)`, `writeSession(key, value)`,
     `removeSession(key)`. Each wraps both the property access (`window.localStorage`) and the call in one `try` and
     returns `null` or `false` on any throw.
  2. Use it in `lib/format/prefs.ts` (`snapshot` and `update`), `components/suit/Interactions.tsx`, and
     `lib/entities/savedViews.ts`. In savedViews, change the default arguments to a small adapter over `readLocal` and
     `writeLocal`, so the signature stays testable. `lib/mine/storage.ts` keeps `probeStorage` (lists need the per-tab
     memory fallback); `lib/mine/dot.ts`, `components/auth/memory.ts`, `ThemeToggle.tsx`, `lib/globe/*`, `GlobeShell.tsx`
     and the search hand-off are already guarded and can move to the helper later.
  3. Add a lint rule (`no-restricted-properties` / `no-restricted-globals` for `localStorage` and `sessionStorage`) with
     `lib/storage/safe.ts` and `lib/mine/storage.ts` as the only allowed files, so a new reader cannot bring this back.
  4. Add an e2e that installs an init script whose `localStorage` and `sessionStorage` getters throw `SecurityError`, then
     visits `/`, `/trips/`, `/trips/dolomites-2027/`, `/places/lago-di-braies/`, `/globe/` and `/mine/`, and expects no
     `pageerror` and no "couldn't load". On `/mine/` it expects the storage-blocked empty state of spec 5.4.
  5. Measure the start JS on the trip page: the helper must cost under 150 B (it replaces inline `try` blocks), or the
     change fails the budget.
  - Owner: a small cross-cutting lane (it touches shared start-chunk files), `travel-builder` on Sonnet with this
    finding as the brief. Severity in `docs/v2/build/UI-NOTES.md` is raised from "Important" to Must.

### I1. Important: Print from Mine prints the wrong thing, and on iPhones probably the wrong page

- **Screen:** `/mine/`, row menu > Print, every width.
- **What is wrong:** `printOpened()` in `web/components/mine/MyTrips.tsx` loads the trip page into an off-screen
  1024 x 768 same-origin iframe, waits a fixed 1.5 s after `load`, and calls `contentWindow.print()`. Four problems:
  1. **It does not print the print view.** The trip's print model (`TripPrintView`, Day 1 to N with the profile) is mounted
     only by `ExportMenu` when the visitor picks Export > PDF (`setPrinting`, then `data-print-model` on `<html>`). The
     iframe never takes that path, so it prints the interactive page through the plain print CSS. The spec promises "the
     public page's print view with the copy's profile" (5.2). Paper is what a family takes to the trailhead (T2).
  2. **iOS.** Every iOS browser is WebKit, and WebKit has a long record of `iframe.contentWindow.print()` printing the
     top document (here: Mine) or nothing. The builder flagged this as untested. The phone is where the 90% are (P7).
  3. **The timer races.** On a slow phone, 1.5 s after `load` is not "after hydration and the timeline": a half-built page
     prints with nothing to say it is incomplete.
  4. **Weight.** A whole trip page (JS, photos, map code) loads in a hidden frame and stays for 60 s. That breaks the
     spirit of P8 and P9 on phones for a feature that a link can do.
- **Decision:** the iframe approach is not acceptable. Build the spec's one-shot key, with `ExportMenu` (which owns the
  print model) as its reader:
  1. `MyTrips.tsx`, `onPrint`: `writeSession('travel.mine.print', slug)` (helper from C1), then
     `router.push(openHref(item))`. Same tab, no frame. Delete `printOpened`.
  2. `web/components/actions/ExportMenu.tsx` (trip target only): on mount, if `readSession('travel.mine.print') ===
     target.slug`, remove the key at once, wait for `data` and the page's timeline session (`getTimeline(slug)`, the
     signal the print view already uses), then `setPrinting(forPage(data, session))`. It reuses the existing double-rAF
     `window.print()` and `afterprint` clean-up, so Mine and Export > PDF print the same paper. No timer.
  3. Storage blocked: the key cannot be written, so Print opens the trip page like Open, and Export > PDF is one tap away
     on the cover. Do not fall back to a URL key: a shared or bookmarked link must never open a print dialog (spec 5.2).
  4. Check by hand on Safari macOS and on an iPhone that the dialog opens without a gesture. If WebKit refuses a print
     after navigation, the reader shows a notice banner above the cover instead (components 5.4, notice): "Ready to print
     Dolomites with your dates." **Print** (secondary sm, calls the same `setPrinting`). Never a second auto-print.
  - Owner: `ExportMenu.tsx` belongs to TRP-GL's files, so the coordinator either hands those few lines to the NAV-2
    follow-up with TRP-GL's agreement or gives TRP-GL the reader and NAV-2 the Mine half. One commit should land both
    halves, so Print is never a dead item.

### I2. Important: in Change dates, "PDF: print" prints the Mine page

- **Screen:** `/mine/`, row menu > Change dates, the sheet's "Take it with you" list, every width.
- **What is wrong:** `ExportList` in `web/components/actions/CopySheet.tsx` renders `PDF: print <trip>` with
  `onClick={() => window.print()}`. Opened from Mine, that prints `/mine/` with the sheet over it. On the trip page the
  same button prints the raw page rather than the print view (same cause as I1.1).
- **Why it matters:** a button labelled with the trip's name that prints something else breaks trust (P4), and the
  visitor finds out only on paper.
- **Fix:** in `ExportList`, take a `print?: () => void` prop and render the PDF button only when it is given. The trip-page
  sheet passes a function that asks `ExportMenu` to print, for example a `travel:print` window event that `ExportMenu`
  answers with its `setPrinting` path. Mine's Change dates passes nothing, because Print is one item away in the row menu.
  The amended spec (Amends) says that in Change dates the list holds the calendar, GPX and CSV only.

### I3. Important: menu items are 40 px on phones

- **Screen:** `/mine/` row menu at 320 and 390, light and dark. Measured from the shots: items are 80 px apart at 2x, so 40
  CSS px. The same applies to every `Menu` on a phone (Export, Saved views).
- **What is wrong:** components 5.2 says "items 40 px (phone 48)", and the `Menu.tsx` comment says the same, but `ui.css`
  only sets `.menu-item { min-height: 40px }` with no phone rule.
- **Why it matters:** the menu opens near the bottom bar, and the destructive Remove is the last item, 40 px under Change
  dates. A one-handed mis-tap at the trailhead (S8 thumb reach, T2) removes a trip. Undo exists, but the target should
  not invite the slip.
- **Fix:** `web/components/ui/ui.css`, in the existing `@media (max-width: 639px)` block:
  `.menu-item { min-height: 48px; }`. Re-shoot `mine-menu-320/390`. The menu then measures 5 x 48 + 9 (divider) + 16
  (padding) = 265 px and still flips above the trigger when it does not fit, as it does now.

## 3. Should fix

1. **The cap state leaves "Copy to my trips" active and hides the way out.** Screen: `sheet-cap-*`; at 320 the footer note
   wraps to six lines beside the button, and "Open Mine" is a text link on the sixth line. Pressing the primary again does
   nothing new. P4, P7. Fix in `CopySheet.tsx`: when `problem === 'cap'`, the footer's primary becomes
   `<ButtonLink variant="primary" href="/mine/?show=trips">Open Mine</ButtonLink>` with **Cancel** (ghost) beside it; the
   cap sentence stays as the note, and the inline link is removed. Below 640 px, when the note is a prompt or a problem
   (replace, cap, error), stack it above the buttons at full width (`.copy-foot { flex-direction: column; align-items:
   stretch }` for that state), so the buttons stay in the thumb zone.
2. **The copy toast fires while the modal sheet is open.** Screen: `sheet-done-320/390`. The toast covers the CSV and PDF
   buttons for 6 s. At 1440 it straddles the sheet's left edge. Because the sheet is a modal `Dialog`, the toast region is
   outside the focus trap, so its Undo is not reachable by Tab (components 5.3 requires it to be) and may not be
   announced. Fix: on the done step, put **Undo** in the sheet's footer as a ghost button after **Done** (it runs
   `undoSave` and returns to the form, as the toast's action does now), and raise no toast while the sheet is open. The
   done step already says what was copied. Spec 7 is amended below.
3. **Focus is lost after removing the last Upcoming row while Past is closed.** `remove()` in `MyTrips.tsx` picks the
   next row from `flat`, which excludes the closed Past rows, so `next` is null. It then looks for `.empty a`, which does
   not exist because the list is not empty, and focus falls to `<body>`. Fix: when no next row exists and `groups.past`
   is non-empty, focus `#mt-past .mt-toggle`; otherwise the empty state's primary; and if neither exists, `#mine-tab-trips`.
   Add a case to `tests/e2e/mine-trips.spec.ts`.
4. **The two-column list reads across, not down.** Screen: `mine-list-1440`. The soonest trip is on the left, the next
   on the right, the third back on the left, so dates jump when you read down a column (the builder's own note). P3. Fix
   in `my-trips.css` at 1024 px and wider: replace the grid with `columns: 2; column-gap: var(--s-8)` on `.mt-list`,
   `break-inside: avoid` on `.crow`, and draw each row's top border instead of its bottom border (with the list's bottom
   border closing the column), so both columns start with a line. Keep one column for Past when it holds a single row.
5. **Change dates loses the season window.** `MyTrips` opens the sheet without `trip.window`, so moving a copy to
   November shows no "outside the season" caution and the calendar loses its Trip season marks (T1). Fix: in
   `CopySheet.tsx`, when `trip.window` is undefined, take it from the export model once `data` loads (the same
   `seasonWindow(months)` the trip page uses). If `TripExport` has no months, add them to the export model, never to the
   copy.
6. **One error string covers every failed write.** `problem === 'error'` always reads "This browser holds trip copies this
   version of the site cannot change...", which is true only for `newer`, `corrupt` and `invalid`. Fix: map the reasons
   in `CopySheet.tsx` and in the Remove toast in `MyTrips.tsx`:
   - `quota`: "This browser is out of space for this site, so nothing was written. Take the files below."
   - `changed`: retry once silently; if it fails again, "Your trips changed in another tab. Try again."
   - `blocked` or `unverified`: the session-only path, as for a blocked probe.
7. **The signed-in chip overlaps line 3.** `.crow-chip` is absolutely placed at the bottom right of the row. At 320,
   line 3 ("14 days · 2 adults, 1 child", about 203 px) runs under it. Not visible yet (sign-in is off), but it ships with
   sign-in. Fix: put the chip in the row's grid as a fourth area under line 3 (`'photo chip'`), as spec 5.2 says ("after
   line 3"), and add a signed-in shot at 320.
8. **Missing evidence.** Before the next review the verifier shoots these at 320 and 1440, light and dark: the session-only
   done step (calendar first, caution banner); the "N older copies did not fit" banner; the Change dates sheet and its
   toast; the Remove toast with Undo, then after Undo with focus on the row; Past closed (the default); a copy made from
   the trip page whose row shows the cover photo (the snapshot's `/img/` path); 200% zoom of a row at 390; and a keyboard
   walk of spec 8 (menu arrows, Esc back to the trigger, focus after Remove and Undo).

## 4. Polish

1. **The group count sits 1,800 px from its label at 1440.** "UPCOMING ... 3" spans the full content width. From 1024 px,
   set the count next to the label ("Upcoming · 3"), as the spec's 1440 sketch shows; keep it right-aligned below 1024.
2. **The Remove button's hit area is clipped.** `.crow-inner { overflow: hidden }` clips the top 3 px of the 44 px padded
   hit area of the sm Remove button (top 4 px, 30 px tall). Apply `overflow: hidden` only while collapsing
   (`.crow[data-collapsing] .crow-inner`), or set `.crow-act { top: 7px }`.
3. **The done sentence repeats the length.** "Dolomites, 13 nights, 14 days from Thu 1 Jul 2027, 2 adults, 1 child": the
   catalogue title already holds a length. Put the facts on their own line after the title: "14 days from Thu 1 Jul 2027 ·
   2 adults, 1 child". The trip title itself belongs to the trip data owner.
4. **The sheet title wraps at 320.** "Copy to my / trips" takes two lines and pushes the form down 32 px. Below 360 px,
   step the sheet title down to `--t-row`. This predates NAV-2 (L5).
5. **The NAV-2 UI notes are bullets, not rows.** `docs/v2/build/UI-NOTES.md` asks for one table row per issue. The next
   lane that touches the file should move the four NAV-2 bullets into rows, with C1 as Must.
6. **12.5 px is a literal** in `my-trips.css` (`font-size: 12.5px`). Use the mono-small type token if tokens.md has one. If
   not, it matches spec 5.2 and can stay.

## 5. Deviations the builder asked about

| Deviation | Ruling |
|---|---|
| Print through a hidden same-origin iframe, `print()` after 1.5 s | **Rejected** (I1): wrong paper (no print model), WebKit risk on iOS, a timer race, a heavy hidden load. Replace with the one-shot `sessionStorage` key read by `ExportMenu` |
| No `cc` in the snapshot (null) | **Accepted.** Trip pages hold no country code yet, and rows do not show one. When a later lane writes the `resolveRefs` answer back into the snapshot (name, photo, country), `cc` fills then. Do not add a country lookup to the trip page for this |
| +128 B trip-page start JS (about 100 B is the shared `resolveRefs` wrapper in `data.ts`) | **Accepted.** One data boundary (P9) is worth 100 B. C1's helper must stay inside the same budget line |
| Dev-only `window.__mineListing` hook | **Accepted as is.** It sits inside `process.env.NODE_ENV !== 'production'`, which Next inlines at build, so the minifier drops the branch and the global is never read in production. No build-time constant is needed. Check it once: `grep -rl __mineListing web/.next/static` after `next build` returns nothing. Add that grep to the budget test if it is cheap |
| Trip page "This page couldn't load" when `localStorage` throws | **Confirmed and raised to Critical** (C1). The fix belongs in a site-wide safe-storage helper plus a lint rule and a throwing-storage e2e, not in each page |

## 6. What is right (keep)

- Rows at 320 and 390: date and countdown ("Sat 3 Jul 2027 · in 250 days") and party ("14 days · 2 adults, 1 child")
  fit with no ellipsis. Only the name truncates, and the full text is in the link's name (T1, D8).
- "No longer listed": the warn glyph, the kept name, the dashed gap chip, no link, and a **Remove** button. Nothing is
  removed silently. The `resolveListing` failure path marks nothing (P8, P9: one data boundary through `resolveRefs`).
- Menu order and semantics: Open, Add to calendar, Print, Change dates, a divider, then Remove in `--crit`. Base UI gives
  `role="menu"`, arrows, Home/End, type-ahead and Esc. The trigger is named "Actions for <trip>" and is 44 x 44.
- Remove: the row collapses over 200 ms (none with reduced motion), the toast has **Undo**, Undo restores the row at its
  place, and focus goes to the next row (except S3).
- Open carries the profile codec's query and never the children's ages, only the youngest band.
- Copy sheet: the replace prompt and the cap strings are the spec's words; the done step leads with **Open in Mine**; the
  footer note is "Kept in this browser." with sign-in off. Nothing says "saved" (spec 7).
- The legacy drafts move once, before the first read, with `kept` feeding the "did not fit" note.
- Colour comes only from tokens; no literal colours in `my-trips.css`; no green, no purple.
