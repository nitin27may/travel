## Steps

1. **Prototype snapshot.** `web/scripts/snapshot-prototype.mjs` bundles `prototype/src/data/{trip,places,trails,public-trips}.ts`
   with `rolldown` from `prototype/node_modules` (React aliased to a stub exporting `useSyncExternalStore`,
   `useMemo`; the store import in `trips.ts` is not needed, do not bundle `trips.ts`), imports the bundle, keeps
   only data (`TRIP`, `PLACES`, `TRAILS`, `ACCESS`, `CHECK_KINDS`, `LINK_KINDS`, `PUBLIC_TRIPS`), and writes
   `web/data-snapshots/prototype.json` with keys sorted. **`TRIP` is household data: snapshot it through an
   allow-list**: `id`, `title`, `start`, `nights`, `zone`, `days`, and per item `id`, `placeId`, `time`, `variant`,
   `note`. Never `travellers`, `who`, `reservations` details (codes, costs, phones, emails, addresses, seats,
   payment, attachments, notes), `tasks` or `lists`. Reservations become generic Logistics rows by kind and day
   only ("Flight · Toronto to Venice", "Car hire · Venice airport"). Item notes that name a traveller are dropped
   (test with the names in `TRIP.travellers`). `--check` exits 1 if the file would change. Commit the
   JSON. If `prototype/node_modules` is missing the script says how to install it (`npm install` in prototype/;
   see design/prototype.md) and exits 1; the web build itself never runs it.
2. **Photo credits.** `web/scripts/fetch-photo-credits.mjs` collects every Commons file used by
   `locations.json` images and gallery files without author or licence, calls
   `https://commons.wikimedia.org/w/api.php?action=query&prop=imageinfo&iiprop=extmetadata|url&titles=...` with at
   most 50 titles per request, **one request at a time** with a 2 s pause and a descriptive User-Agent, and writes
   `web/data-snapshots/photo-credits.json` (file, author as plain text, licence short name, licence URL, source
   URL). Run it once; commit the result. A 429 stops the script and keeps what it has.
3. **Slugs.** `web/lib/public/slugs.ts`: the trip slug table in README 2.3 (legacy folder to slug), place slugs
   from the kebab name with the area appended on a collision (patterns 1.2), stable across builds (unit test with
   the two Moss Glen Falls case and every current place). Old place URLs
   (`/places/<cc>/<region>/<area>/<place>/`) map to the new slug: `legacyPlaceRedirects()`. Write them, plus
   `/globe/*  /globe/  200` and the existing `/locations/*` rule, into `web/redirects.json` (generated by
   `pnpm --dir web snapshot`; keep it deterministic).
4. **Places.** Merge `locations.json` (identity, slug and area chain win), prototype `PLACES` and `TRAILS` +
   `ACCESS`. De-duplicate when the Wikidata id matches, or the normalised name matches within 300 m; the merged
   record keeps every source and the prototype's facts and links. Map kinds with README 2.4. Area chain for
   prototype places: an explicit table from the prototype `area` strings to IT › South Tyrol / Veneto / Trentino
   › area (write it out; no geocoding). Prototype example stays are not places (README 2.4).
   Every point carries `pointSource` and its source licence; every line carries `exportable: boolean` (true only
   for OSM-derived lines with an `osm_ref` or official sources whose licence allows reuse). L5's export guard reads
   these; never record a Google-sourced coordinate.
5. **Trips.** Build `PublicTrip` for every folder in the slug table, honouring `MANIFEST` `private` (fail closed,
   reuse `parseVisibility`). Depth per README 2.3:
   - Dolomites: days from `TRIP.days` with each item resolved to its place; base per day; drive minutes from the
     prototype estimate, `driveIsEstimate: true`.
   - Rockies: days from `itinerary.json`, tracks A/B/C as `tracks[]` each with its items; items resolved to
     trails, sights, adventures; stays from `bases.json` with nights; bookings into Logistics.
   - Summary trips: days from `PUBLIC_TRIPS` stops; `drive` stops become the day's drive, not items.
   - Overview trips: no days; `honesty` includes `overview`.
   Categories per patterns 3.4 rules: one item, one category; an item on two days is one entry with
   `days: [3, 5]`; access folded into its subject; Logistics items carry `bookBy` when known; empty categories
   present with an empty array (the UI greys them). Order fixed.
6. **Photos.** `Photo` objects with `url` = `https://commons.wikimedia.org/wiki/Special:FilePath/<file>?width=<w>`
   and a `srcset` helper for 480/960/1600; credit from gallery.json or photo-credits.json; no credit, no photo.
   Trip cover: the first gallery photo of the first section unless the hub hero has a credit.
7. **Completeness.** `completeness.ts`: `computeCompleteness(place) -> { level, passed, total, notTracked, failed[] }`
   with the common checks D1 to D5, U1, U2, C1 to C4 and the kind U checks whose fields exist (trail: distance,
   climb, time, trailhead point, season; lake and viewpoint: access, season; stay: nights is trip-level, skip).
   `total` counts tracked checks only; `notTracked` is the profile's total minus tracked. Unit tests for a trail
   from `TRAILS`, a locations.json lake, and a Draft place with no source.
8. **Honesty.** `honesty[]` per place and trip from README 2.6, including the TODO row's unconfirmed trail
   points (list them by id in `honesty-overrides.ts` with the TODO text as the reason).
9. **Globe index.** `globeIndex()`: places and listed trips grouped by continent, ISO country, state (region),
   district (area) with counts; trips pinned at their first base; `globePaths()` lists every country, state and
   district path with at least one item, using the slugs the globe's admin files use (check
   `legacy/globe/assets/admin/*` names and `gazetteer.json`).
10. **Wrap the old loaders.** `listTrips`/`listPlaces` reuse `web/lib/data/*` so the allow-list and the privacy
    test keep working; extend the privacy test so no private slug, title or legacy URL appears in any adapter
    output or in `web/out`.
