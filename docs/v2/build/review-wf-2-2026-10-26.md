## Verdict

**Merge after fixes.** The workflow is sound against the threats that matter on a public repository: no secret is
referenced, the workflow token is read-only at both levels, there is no `pull_request_target` or `workflow_run`, every
untrusted value reaches the shell through `env:` rather than `${{ }}` inside `run:`, and the four pins are real. Two items
must be done first, and one of them is a GitHub setting, not code.

## Nits

- `MAC_ONLY` is also hard-coded in `plan_to_outputs.py` (`("web.timing",)`) while `gate.py` decides by `slot == "timing"`; a second timing suite would be MAC_ONLY in the gate and still count as a planned `web` group in the outputs. WF-3 moves it to the map; until then derive it from the plan rows' `status`.
- The decoy `10.5 / -140.5` is written in three places (`check.yml`, `guard_env.sh`, `core/test/setup/home-point.ts`). The guard could read it from the TS file.
- `docs_only` and `specs` outputs are unused in phase 1; `summary` needs no `contents: read` (it does not check out).
- `pytest>=8` floats; pin a version.
- S1.1 of ENGINEERING-STANDARD says no new top-level folder. `.github` is the exception the owner approved with this plan; say so in the tree contract's reason so S1.6 is visibly met.
