# Travel

Trip plans, a saved-places list and the site that publishes them to https://nks-travel.pages.dev/.

## What lives where

| Path | What it is |
|---|---|
| `data/` | The system of record, JSON in git: `locations/` (places), `capture/`, `suitability/`, `relevance/` (research records and sidecars), `vocab/` (the type tree and tags), `schema/` (mostly generated from `core/`), `reference/` (countries, licences) |
| `core/` | `@travel/core`, the TypeScript package that owns the schemas, the validator and the research CLIs in `core/bin/` |
| `web/` | The Next.js app: home, trips, places, place pages, about the data |
| `legacy/` | The hand-built trip pages, their `PLAN.md` and builders, the old globe and the design system. They stay at their current URLs until backlog 7.11 |
| `research/` | All research: the method, per-type checklists, output formats and templates, raw captures, per-trip findings, run notes, audits and reports. Never published. Map: `research/README.md` |
| `tools/` | Python tooling (locations, publish, gallery, hooks, relink) and its tests, plus `check-all.sh` |
| `docs/` | Decisions: the plan, specs, design and build briefs in `docs/v2/` (start at `docs/v2/PLAN.md`); superseded documents in `docs/archive/v1/`. See `docs/README.md` |
| `prototype/` | The old Vite planner prototype; retired in cleanup CLN-3 |
| `.claude/` | Project agents and skills, thin wrappers that point into `research/` |
| `.site/` | The staged site, generated by the publish step. Gitignored |

The folder rules are in `CLAUDE.md` ("Folder contract") and `docs/v2/CLEANUP-PLAN.md`.

## Add a place

Use the `location` skill ("add X to the locations list"), or run the tool directly:

    python3 tools/locations.py add "Lake Louise"
    python3 tools/locations.py edit <id> --status shortlisted
    python3 tools/locations.py visit add <id> --date 2027-07

The tool resolves coordinates through Wikidata, then Nominatim, and files the place under country, region and
area. Every write validates the store and rebuilds the generated views. Do not edit `data/locations/WISHLIST.md`,
`legacy/locations/index.html` or the globe pins by hand. Details: `data/locations/README.md`.

## Build and publish

    python3 tools/publish.py --dry-run      # build the app, stage .site/, check every old URL is still there
    ./publish.sh                            # the same, then deploy to Cloudflare Pages

Publishing runs these steps in order, and stops at the first failure:

1. `tools/locations.py build` regenerates the list page, the wishlist and the globe pins.
2. `tools/hub.py --json` writes the legacy trip list for the app (`web/.generated/legacy-trips.json`).
3. `pnpm --dir web build` exports the app to `web/out/`.
4. `web/out/` is copied into an empty `.site/`.
5. Each legacy route is copied unless the app already wrote that path. A clash is an error, unless
   `data/trips/<slug>/trip.json` has `trip.web_published = true`, in which case the app wins.
6. `_redirects` is written last from `web/redirects.json`.
7. Every URL in `tools/tests/fixtures/served-urls.txt` must still resolve. A missing one fails the publish.

`python3 tools/publish.py --dry-run --no-web` stages only the legacy pages and the Python home page (no app).
`HUB_TODAY=2026-10-17` pins the date used for "In N days" badges so two builds can be compared byte for byte.
`SITE_ORIGIN` sets the host used in canonical and Open Graph tags (default `https://nks-travel.pages.dev`).
`NEXT_PUBLIC_CF_BEACON_TOKEN`, when set at build time, adds the Cloudflare Web Analytics beacon to app pages
(never to legacy pages).

## Run the app locally

    pnpm install
    pnpm --dir web dev                       # http://localhost:3000

The list pages keep all their state in the URL: `/places/?country=CA&kind=lake&view=table&sort=-elevation`.
Shareable links work for every view and filter.

## Tests

    bash tools/check-all.sh                  # everything: python, core, schema, data, web typecheck, lint, test, build
    python3 -m pytest tools/tests -q         # python only
    pnpm --dir web test                      # unit, privacy, budget, Open Graph, fonts (builds the app three times)
    pnpm --dir web e2e                       # Playwright: stages .site/, then checks parity with the legacy list page

First run of the Playwright suite needs the browser: `pnpm --dir web exec playwright install chromium`.
`PW_REUSE_SITE=1` skips re-staging `.site/`; `SKIP_WEB_BUILD=1` lets `pnpm --dir web test` reuse `web/out/`.

## Known issues

- `pnpm install` exits non-zero until the root `pnpm-workspace.yaml` says what to do with the `unrs-resolver`
  build script (`allowBuilds: { unrs-resolver: false }`). Nothing is broken; the install itself completes.
- Photos are hot-linked from Wikimedia Commons. Offline, or when Commons rate-limits, cards show a tinted
  placeholder with the place kind instead.
- The Map tab on list pages is present but disabled until the map view is built (P3b).
- Legacy pages still load their fonts from Google Fonts; the app self-hosts its fonts in `web/public/fonts/`.
